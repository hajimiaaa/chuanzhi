# 课径 CoursePath

> 把大学四年的培养方案，从一张看不懂的 PDF，变成一张能拖拽调整、实时算学分、自动查冲突的交互式路径图。

**参赛作品** — 第九届传智杯 · 全国高校 Vibe Coding 开发挑战赛 · B 组（个人赛）

---

## 这是什么

选课真正的困难不是"选哪门课好"，而是**约束满足**：

- **学分结构** — 必修 / 专业选修 / 通识 / 实践，每类各有最低学分要求
- **先修链** — A 必须先修 B，才能修 C
- **时间冲突** — 同一学期开课时间重叠
- **个人多目标** — 想保研 / 想早修完 / 想大四留出实习时间

课径把这些问题变成一个可视化规划器：拖动课程到不同学期，**实时**看到学分进度变化、冲突红色高亮、先修链断裂警告。

**特别针对的场景：转专业学生。** 这个场景的痛点不是"选课选得好不好"，而是**信息到不了手**：

> "转专业难吗，通识课分数真的要卡到 70 分吗，转专业除了学生守则上的要求，还有其他特殊要求吗"
> —— 某校园社区，浏览 822 次，5 条回复

调研发现（见 `docs/用户调研.md`），学生真正卡住的地方有两处，都在现有工具的覆盖之外：

- **转专业前 · 查不清规则** — 挂科要求、分数门槛、笔试面试、专业与校区限制，这些信息官网都有，但散落在文件里，学生只能靠学长学姐的口语经验拼图，答案还互相矛盾（同一个问题，我们收集到过三个不同回答）。
- **转专业后 · 算不清学分** — 已修课程如何折抵、要补修哪些课、什么时候排得开，**零工具、纯人工**：对着学校文件自己核算。

课径把这两件事都变成看得懂、能动手算的图：**官方文件 → 结构化数据 → 可交互的路径图**。

**这不是我们的推测——学校自己的文件就是这么要求的：**

> 学生应**充分了解所申请专业的相关情况**，根据自己的志趣和能力慎重选择，不可盲目跟从，以免转专业后造成学习不适应，影响学业。
> —— 枣庄学院《关于做好 2024 级普通全日制学生转专业的通知》

校方明确要求学生"充分了解专业"，却没有提供任何工具。而规则本身还是分散的：**1 份校级通知 + 21 个学院各自网站公示的方案 + 学分认定办法**……学生要拼出完整答案，得跨 4~5 份文件、21 个网站。（依赖图见 `docs/校方文件分析.md`）

> 边界说明：课径解决的是**信息问题**，不解决**学业能力问题**。转专业笔试考的是高中物理与高等数学，绩点门槛是硬指标——这些我们不承诺覆盖。

## 10 分钟极速复现指南

> 本节面向评审专家。**无需任何 API Key 即可完整运行核心功能。**

### 1. 环境要求

| 依赖 | 版本 | 说明 |
|---|---|---|
| Python | 3.11+ | 后端 |
| Node.js | 18+ | 前端 |
| Git | 任意 | |

> ⚠️ Windows 用户注意：若 `python` 命令报错，请改用 `py -3.11`。

### 2. 克隆仓库

```bash
git clone <仓库地址>
cd 课径
```

### 3. 后端

```bash
py -3.11 -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # macOS / Linux

pip install -r backend/requirements.txt
cp .env.example .env            # 无需填写任何值，留空即可运行

# ① 数据自检 —— 纯标准库，不装依赖也能跑
py -3.11 tools/validate_programs_json.py

# ② 约束引擎单测 —— 应全部通过
cd backend
pytest -q

# ③ 启动服务 —— ⚠️ 工作目录必须是 backend/，否则 app 包无法导入
uvicorn app.main:app --reload --port 8000
```

### 4. 前端

```bash
cd frontend
npm install
npm run dev
```

打开 http://localhost:5173 即可。

### 5. 关于 AI 功能

应用**默认运行在 mock 模式**，使用内置样例数据，所有核心功能（学分校验、冲突检测、路径规划、可视化）**均无需联网即可完整演示**。

mock 不是一段无人调用的死代码——访问 `GET /api/health` 会直接看到 `"llm": {"provider": "mock"}`，
调用 `POST /api/llm/explain` 则会返回一段由内置规则生成的中文解释，**无需任何 Key 即可现场验证这条链路**。

若需体验真实的大模型能力，在 `.env` 中填写 `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL` 后重启后端即可
（后端启动时会自动读取 `.env`，三个变量齐全才切换到真实模型，否则回退 mock 并打印提示）。

### 数据与依赖分层

| 层 | 文件 | 依赖 |
|---|---|---|
| 领域 / 数据 | `config.py` `models.py` `store.py` | **仅标准库** |
| 引擎 | `constraints.py` `planner.py` `llm.py` | **仅标准库**（LLM 走 `urllib`） |
| 边缘 | `schemas.py` `main.py` | fastapi / pydantic |

这样分层是为了：**约束引擎与数据校验完全不依赖 web 栈**，因此
`py -3.11 tools/validate_programs_json.py` 可以在不装 fastapi、不开 venv 的情况下跑通，
形成一条独立的复现链。

## 技术栈

- **前端**：React + Vite + TypeScript，React Flow（依赖图）、ECharts（学分统计）
- **后端**：FastAPI + **JSON 文件存储**（数据即文件，评审可直接打开核对，无需数据库即可零配置复现）
- **大模型**：可插拔适配层，零第三方依赖，无 Key 时自动降级为 mock

> 关于持久化：当前数据以 JSON 文件形式存放于 `data/`，每个文件都配有可复现的生成/校验脚本。
> SQLite 顺延至「需要保存用户自己编辑的规划」时引入——在那之前引入只是多一层目前用不上的复杂度。

## 开发过程留痕
