# 对预提交评审意见的回复

> **评审意见（2026-10）**：若因产品原因、功能不完善导致学生未能取得学分，该怎么办？
>
> 本文回复对应 2026-11-10 的修改。**每条结论都可以用文末的命令复现**，不是表态。

---

## 一、我们如何理解这条意见

它不是一个"加一句免责声明"的要求，而是四个连续的问题：

| 层 | 问题 | 我们原来的状态 |
|---|---|---|
| 输入层 | 培养方案是不是真的？ | 样例数据，只有 1 个专业 |
| **计算层** | **算出来的数对不对？** | **跨专业同名课被误判，公共课全部算成"需补修"** |
| 输出层 | 结论语气与不确定性匹配吗？ | 五类混在四个数字里，语气是确定的 |
| 责任层 | 学生照做踩坑怎么办？ | 无核对单、无导出、无"以教务处为准"的下一步 |

第二层是这次修改的重点：它是一个**能被单测复现的缺陷**，不是措辞问题。

---

## 二、改了什么

### 2.1 计算层：跨专业同名课不再被误判为「需补修」

**问题。** 原实现只按**课程号**精确匹配。跨专业转学时，公共课（高数、英语、体育、思政）
在原专业往往有另一套课号——它们会被判成"需补修"，而目标方案里的对应课程也留在
「需补修」里。学生看到的是同一门公共课在两张清单里各出现一次，
照着做就会重复选课、占掉本该修专业课的学期容量。

**修法。** 新增第五类 **「可能可折抵」**：

```
第一遍：课号完全相同        → 已认定 / 需重修（高置信）
第二遍：课名归一化后相同
        且学分相同、课号不同 → 可能可折抵（中置信，需教务处确认）
都对不上                    → 需补修 / 待认定
```

课名归一化只做确定性处理（全角转半角、去空白与标点），**不删括号里的序号**——
「高等数学A(一)」和「高等数学A(二)」必须保持可区分。

我们**仍然不判断这些课能不能折抵**。判定标准各校完全不同（有的给换算式，
有的要求"课程目标等效"），没有枣庄学院的《学分认定管理办法》就不猜。
变化只是：把"需要人去确认的课"从"要重修"里挑出来，单独成一类。

**守恒。** 前四类（不含「待认定」）的学分之和**恒等于培养方案总学分**：
每门方案课必须恰好落在一类里，不重不漏。这条是硬断言，不是文档描述。

### 2.2 数据层：演示数据不再自相矛盾

原来的示例成绩单只有 **4 门课**，导致其余 38 门全部落进"需补修"，
界面主视觉是「38 门需补修 / 110 学分」，而培养方案总共只有 123 学分——
评委的第一反应必然是"这产品算错了吧"。

现在换成一份 **33 门**的示例成绩单（软件工程 → 计算机科学与技术），覆盖全部五种结果：

| 类别 | 门数 | 学分 |
|---|---|---|
| 已认定（课号相同且通过） | 17 | 52 |
| 需重修（课号相同但未通过） | 1 | 4 |
| **可能可折抵（同名同学分、课号不同）** | **10** | **28** |
| 需补修（对不上） | 13 | 39 |
| 待认定（原专业独有） | 5 | 12 |
| **前四类合计** | | **123 = 培养方案总学分** |

### 2.3 输出层：语气与不确定性对齐

- 五类分区展示，每类写明**置信度**与**该做什么**；
- 「可能可折抵」**不并进「已认定」**，界面上明确写"确认前不要当成已修"；
- 「待认定」单独说明：不是我们漏了，是缺认定办法；
- 统计区注明"前四类合计严格等于培养方案总学分，不存在重复计算"。

### 2.4 还没做完的（如实列出）

| 事项 | 状态 | 下一步 |
|---|---|---|
| 可打印/签字的核对单、纠错入口 | **未实现** | 省赛后第一优先级 |
| 真实培养方案（当前 1/108 个专业） | 未完成 | 需要教务处公开的培养方案原件 |
| 跨专业折抵判定 | 不做 | 需《学分认定管理办法》 |
| 排课时段（时间冲突） | 逻辑已实现，数据未接入 | 需排课表 |
| 学院级分数门槛 | 无数据 | 需 21 个学院的方案 |

**产品立场**：课径输出的是一份**核对草案**，不是教务处的最终结论。
最终认定以教务系统与教务处审核结果为准。

## 三、怎么复现这次修改

```bash
# 后端单测：包含守恒与"每门课恰好一类"两条断言
cd backend && ../.venv/Scripts/python.exe -m pytest -q
#   → 156 passed

# 直接看分类结果（不经过前端）
#   请求体里的 name 是新增字段，用来识别跨专业同名课
curl -X POST http://127.0.0.1:8000/api/plan/credit-gap \
  -H "Content-Type: application/json" \
  -d '{"program_id":"computer-science-2024-sample","completed":[
        {"course_code":"SE102","name":"高等数学A(二)","credits":5,"grade":84}]}'
#   → possible_overlap: ["CS102"]，且 CS102 不再出现在 remedial 里
```

两条关键测试：

- `test_credit_conservation_across_buckets` —— 四类学分之和 == 培养方案总学分
- `test_every_program_course_lands_in_exactly_one_bucket` —— 每门方案课恰好落在一类

## 四、一句话

> 我们没法保证"算得全对"——数据、认定办法、排课时段都还不完整。
>
> 但我们能做到：**把确定的、需要确认的、没有数据的，分成三类如实标出来，
> 并且保证已经算出来的部分不重不漏。**
> 学生拿到的不是一句"还差 13 门"，而是一张写着"哪几条可以直接信、哪几条要去找谁确认"的清单。
