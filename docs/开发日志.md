### 迭代 1 · 2026-10-15 · 用户调研与定位校准

**这轮要做什么：** 完成转专业学生的痛点验证（立项时唯一的卡点），据此确定 MVP 范围。

**实际做成了什么：**

- 收集到两条信源：同学访谈汇总 + 校园社区三条公开帖（其中一条浏览 822 次、5 条回复）
- 建立 `docs/用户调研.md`：含原话摘录、6 条发现、3 项决策，所有结论可追溯到原话
- **定位从「单入口」改为「双入口」** —— 原定位是"转专业**后**的补修路径规划"，改为"认知入口（查清规则）+ 核算入口（算清学分）"
- 确定 MVP 四项范围与砍单顺序（转专业规则查询排最后，第一个可砍）
- 同步更新 README 痛点段、CLAUDE.md 选题描述、备赛手册待办

**卡住的地方 / 遇到的 Bug：**

- 桌面上的 `访谈.txt` **第一次读取时是 0 字节**——差点直接当成"材料不存在"跳过
- 访谈记录是**汇总转述**，不是原话，违反《备赛手册》"把原话记下来"的要求
- 最麻烦的一处：**调研结论和项目原定位正面冲突**。原卖点是"会不会延毕"，而访谈里明确说"都不太在意延毕"；社区三条帖子也全部集中在"转专业前"，没有一条提到折抵或补修

**我是怎么引导 AI 解决的：**

- 首先，我没有让 AI"帮我找证据支持这个选题"——那样它一定会找到。不如改用**证伪视角**提问："这批数据支持不支持我们原来的定位？哪里对不上？"
- 然后AI 指出了两处硬冲突：① 痛点集中在转专业前；② 笔试卷的是**高中物理与高等数学**，跟培养方案没关系，这等于当面否掉了"工具能帮学生转专业"这个隐含承诺
- 也就是说 AI **主动划出"我们帮不上什么"的边界**（绩点门槛、笔试），写进文档。与其答辩时被评委戳破，不如自己先划清
- 最后由 AI 提出把核心能力重新定义为"**把官方文件变成结构化数据**"——这样"转专业管理办法"和"培养方案"就成了同一种输入，两个入口共用一套引擎，架构不用分叉

> **这轮最值得讲给评委的一点**：AI 的价值不是"帮我把想法实现"，而是"**在我沉浸于自己的想法时，指出数据不支持它**"。前提是我给了它证伪的任务，而不是背书的任务。

**下一轮要做什么：** 后端骨架（数据模型 + 约束引擎）。约束引擎先做纯函数 + 单测，再接 API——保证演示时冲突检测的结果可预测。

### 迭代 2 · 2026-10-15 · 后端骨架（数据模型 + 约束引擎 + 接口）

**这轮要做什么：** 把调研落到代码上。约束引擎先做纯函数 + 单测，再接 API。

**实际做成了什么：**

- `backend/` 从零建成：`config / models / store / constraints / planner / llm / schemas / main` 八个模块
- 手写了一份**明确标注为样例**的培养方案（计算机科学与技术，41 门课 / 8 学期 / 学分门槛 119 / 每学期上限 26）
- 约束引擎 6 个纯函数 + 90 项单测（今天结束时的数字）
- 9 个接口，真机 curl 全部验证通过
- `tools/validate_programs_json.py` —— **零依赖**的数据自检脚本

**卡住的地方 / 遇到的 Bug：**

这轮抓到三个 Bug，其中两个**不是代码写错，而是文档承诺与实现脱节**：

1. **`planner.py` 报的失败原因是错的。** 一门课排不下时，代码说"开课学期与先修课完成时间冲突"——可那门课**根本没有先修课**，它是因为学期学分上限满了。原因判定写成了 if/else 的兜底分支。**这是单测抓出来的**：我断言"排不下时提示里应含『上限』"，测试红了。

2. **README 的复现指南自相矛盾。** 第 71 行用 `backend/requirements.txt`（说明当前目录是仓库根），第 73 行却直接 `uvicorn app.main:app`（要求当前目录是 `backend/`）。评委照抄，**第一步就 `ModuleNotFoundError`**。

3. **`.env` 从来没有被加载过。** README 让人 `cp .env.example .env`、说"填 Key 后重启即可"，但 uvicorn 不读 `.env`，仓库也没装 `python-dotenv`。**这条路从未通过**——想试真 Key 会永远静默降级回 mock，还不报错。

**我是怎么引导 AI 解决的：**

- 我没有让 AI"写完就交"，而是**要求每个模块都有可执行的验收命令**。正是这条让第 1 个 Bug 暴露出来——AI 写了单测，单测把它自己写的兜底分支照出来了
- 第 2、3 个是另一类：我让 AI **把 README 的复现指南当成一份要去执行的东西来读**，而不是当成说明文字。它逐行比对之后发现前后矛盾；`.env` 那条更隐蔽，是靠"读一遍复现步骤然后追代码"才发现的——`uvicorn app.main:app` 后面没有任何加载 `.env` 的环节
- **修法也是 AI 提的**：新建 `config.py`，用 20 行标准库读 `.env`，且**只填空缺、绝不覆盖**已存在的真实环境变量。比装 `python-dotenv` 更可控，也符合项目"少依赖"的取向

> **这轮最值得讲给评委的一点**：三个 Bug 里有两个是**承诺与实现脱节**，而不是算法错误。这类 Bug 不会让程序崩，只会让"按文档走的人"卡住——而我们的提交物里，25% 的分数恰恰压在"评委能不能一键复现"上。所以"让 AI 把文档当成要执行的东西读一遍"，比让它多写一倍的测试更有价值。

**下一轮要做什么：** 前端。先定主视图形态（学期泳道板 vs 依赖图），再定拖拽库，最后才是写组件。

**实际做成了什么：**

- 先做后端流式（纯后端、可独立单测、不阻塞前端）：`Provider.stream` + `sse.py` + `POST /api/llm/explain/stream`，15 项单测
- 前端从零建成：Vite 8 + React 19 + TS 6，约 3000 行、25 个源码文件
- 主视图用**学期泳道板**（八列横排、课程卡可跨列拖拽），拖拽用 `@dnd-kit`

- 学分进度：Hero 数字 + 4 条类别 meter（CSS）+ 每学期堆叠柱（ECharts）
- 前端 32 项单测（reducer / SSE 解帧 / 本地预判）

**卡住的地方 / 遇到的 Bug：**

前端这轮抓到**四个**，最后一个是这轮最有意思的：

1. **专业列表把三种学制都标成"已接入培养方案"。** 我写了个"去掉括号再匹配"的兜底，结果 `计算机科学与技术` / `（春季）` / `(专升本)` 全被认成了同一个专业。可它们是三个不同的招生口径，而且按《通知》本来就**不在可转专业范围内**。

2. **图表图例里混进了"超出上限"。** 那是我用全透明的占位系列挂标记时留下的噪声。

3. **上限 26 的那条线根本没画出来。** 各学期最高才 21 学分，ECharts 把 y 轴自动收到 25，而上限线在 26 —— **落在坐标区外被静默裁掉**。页面看上去一切正常，线就是不见了。

4. **ECharts 只注册了 `BarChart`，我却用一个 `type:'line'` 的系列去挂上限线，该系列被静默丢弃。** 这个和第 3 个叠加在一起：**我截了两轮图都以为线画好了，其实是看错了**。最后是浏览器控制台的一句 `[ECharts] Series line is used but not imported` 把它揪出来的。

**我是怎么引导 AI 解决的：**

- 第 1 个是靠**截图看图**发现的——把渲染结果当成用户看到的样子去检查，而不是假设"代码写了就是对的"
- 第 2、3 个同样来自看图：图例里多了一项、坐标轴上没有那条线
- 第 4 个换了手段：我发现光看静态截图不够（因为线本来就不该出现，看不出异常），于是**让 AI 装了一个浏览器驱动（playwright-core，用系统已装的 Edge，不下载浏览器）真的去拖了一下**，并收集控制台错误。这一条命令同时验证了四件事：拖拽能不能用、冲突会不会实时出现、点击能不能联动高亮、流式是不是真的在逐字增长

> **这轮最值得讲给评委的一点**：静态截图验证不了"某个东西**没有**出现"。第 3、4 个 Bug 都是这种——程序不报错、页面不异常，功能却缺了一块。逼出它们的不是更仔细的看代码，而是**换一种验证手段**（从看截图换成驱动真实浏览器 + 收集控制台）。而这恰好也是"为什么宁可用真流式而不是假动画"的同一个道理：**能被证伪的东西才值得信**。

**下一轮要做什么：** `docs/技术文档.md`（提交物里唯一还缺的），然后是演示视频。

### 迭代 4 · 2026-10-15 · 转专业规则模块（认知入口的数据地基）

**这轮要做什么：**

把《关于做好 2024 级普通全日制学生转专业的通知》结构化：挂科要求、分数门槛、笔试面试、专业与校区限制。
数据放 `data/rules/`（带溯源块），转换脚本放 `tools/`（纯标准库），查询接口 `/api/rules`，配单测。**先不动前端**——
这是 MVP 第 4 项，对应「认知入口」，此前一直是空壳。

**实际做成了什么：**

- `data/rules/转专业通知-枣庄学院-2024级.json`：**17 条条款 / 5 个时间节点 / 5 处缺口**
- 条款按「学生想知道什么」分 8 类（准入情形 / 挂科 / 分数 / 考核 / 专业限制 / 校区 / 次数 / 学分认定），
  每条带原文条号与逐字引用
- `tools/build_rules_json.py`（人工分类 + 机器校验）、`tools/validate_rules_json.py`（零依赖自检）
- `GET /api/rules`、`GET /api/rules/{id}?category=`，真机 curl 验证 200 / 404 / 422
- 单测 90 → **134 项**（新增 44 项）
- 技术文档 / README / CLAUDE.md 同步

**卡住的地方 / 遇到的 Bug：**

1. **点名的四类里，有两类这份通知根本没有。** 读完全文（75 行）才发现：只有「挂科要求」和
   「专业限制」是白纸黑字写着的。「分数门槛」和「笔试面试的具体形式」——通知只说
   「转入人数超过招生数 30% 时，按**转入学院制定的考核方案**择优」，而 21 份学院方案一份都没到手。
   「校区限制」通知全文未提。**这四类里有三类，按常识补一个数字上去是最省事、也最容易蒙混过关的做法。**

2. **引用回溯脚本第一次运行就红了，抓出我自己的臆造。** 我写的条款引用是
   「拟转入学生**已修读课程**学习情况」，原文是「已修课程学习情况」——多了一个「读」字。
   值得注意的是：`docs/校方文件分析.md` 里那句也是这么摘的，**两处人工摘录犯了同一个错**。
   光拿产物对照分析文档不会发现，只有回原文才抓得住。

3. **同一个 JSON，两种形状。** 生成脚本直接 `json.dumps` 人工登记表，登记表里没写的键就省略；
   接口走 `RuleDoc.to_dict()`，输出全部字段（空值补成 `[]` / `null` / `""`）。
   落盘文件和接口响应长得不一样，前端按哪个写都会在另一处踩空。

4. **一条既有纪律否掉了我最初的方案。** 我原本打算给条款加一个 `payload: dict` 透传类别特异的载荷。
   读到 `models.py` 里 `Conflict` 的注释才停下来：
   「刻意不设 `detail: dict` —— dict 字段会让 frozen 变成假象，且 `hash()` 会直接 TypeError」。
   于是改成给 `Provision` 列 7 个显式可选字段。

**我是怎么引导 AI 解决的：**

- **先探事实，再动手。** 我没有直接说"去写"，而是先让 AI 三路并行调查（原始文件清单 / 后端既有模式 /
  tools 约定），并且明确要求：**文件格式要实际用命令行查，不要猜**。这一步的价值在于，它让
  「21 份学院方案不在仓库里」变成一个被实测确认的前提，而不是我的印象。

- **第 1 个问题我没有让它"想办法补上"，而是让它把"补不上"变成产品的一部分。** 我给的原则是：
  该类别下不放条款，改为显式列出缺口——每处缺口写清「依据哪条 + 该去哪里查」。
  更进一步我要求：**缺口的「没有」本身也要能被复核**。于是每处 `not_available` 都带一组
  `absent_keywords`（门槛 / 分数线 / 绩点 / 70），由脚本反向检索，证明这些词在原文里真的一次都没出现。
  学生社区里那个焦虑了很久的「通识课真要卡 70 分吗」，现在的答案是一条可被机器复核的数据：
  **校内通知里没有 70 分这个数字，答案在学院方案里。**

- **第 2、3 个都不是我读代码读出来的，是校验自己抓出来的。** 我要求"每条引用都必须能回原文找到"，
  AI 就把这条写成了生成脚本的前置断言；脚本第一次跑就退出了，把那个多出来的「读」字顶了出来。
  第 3 个同理：落盘过一次、又跟接口响应比过一次，形状不一致才显形。

- 第 4 个是**读既有代码的注释**救的。我没有让 AI 自由发挥，而是要求它"照着现有风格做"——
  这条要求让它必须先把 `models.py` 读进去，也就撞上了那条禁令。

> **这轮最值得讲给评委的一点**：这个模块真正交付的东西，一半是条款，一半是**缺口的清单**。
> 条款部分证明"结构化是可行的"，缺口部分证明"我们知道自己不知道什么"。
> 官方文件没写的规则，编一个数字出来比诚实标注更容易拿分——**但那正是我们在调研里批评其他信息源的地方**。

**下一轮要做什么：** 要么采集 21 个学院方案（缺口指向的就是它），要么把 `/api/rules` 接进前端认知入口。

### 迭代 5 · 2026-10-22 · 前端认知入口（转专业规则视图）

**这轮要做什么：**

上一轮把规则做成了后端能力，但前端一行没接。定位里的**双入口**只有一半在界面上成立：
学生打开应用直接看到四年排课板，认知入口看不见，评委也无从验证。
这轮把它接进前端——顶栏双 tab，规则页做成独立视图。

**实际做成了什么：**

- 顶栏「培养方案 / 转专业规则」双 tab；`view` 状态放在 `PlanProvider` 之下，
  切走再切回，排课编辑与撤销栈都还在
- 规则页双栏：主区按 8 类分组展示 17 条条款（verdict 徽章 + 条号 + 逐字引用 + 结构化载荷），
  侧栏是「查不到的类别」5 处 + 时间线 + 溯源块
- 分类筛选**走后端** `?category=`，响应里的 `filter.matched` 回显命中数
- 前端单测 32 → **53 项**（新增 21 项，覆盖分组顺序、载荷文案、登记表完备性）
- 用 headless Edge 真机驱动验收：双 tab 切换、两种筛选、窄屏单栏、控制台零报错

**卡住的地方 / 遇到的 Bug：**

1. **顶栏 tab 的选中态被 `:hover` 盖住了。** 点完「转专业规则」之后，指针正停在按钮上，
   `:hover` 的灰色背景压过了 `.navtab--active` 的白色底 —— 原因是 `.navtab:hover`
   带伪类，特异性 (0,2,0) 高于单类名 `.navtab--active` 的 (0,1,0)。
   **截图上看不出来**（两种灰很接近），是靠读 `getComputedStyle` 的 `backgroundColor`
   才定位的。

2. **`stats` 不随过滤变化，界面上会像 bug。** 筛到「专业限制」时列表只有 3 条，
   而 `stats.provisions` 仍是 17 —— 上一轮特意设计了 `filter.matched` 来消歧，
   这一轮必须真的把它显示出来（「专业限制 · 3 条 / 全文 17 条」），否则用户会以为漏了。

3. **一个设计取舍而不是 bug：视图状态放哪层。** 放 `App` 层能更早进入规则页，
   但会卸载 `PlanProvider`，用户拖了半天的课切一下视图就全没了。
   放在 `Workbench` 内、Provider 之下，代价是规则页要等专业列表加载完才可达 ——
   本地加载不到 1 秒，这个代价可以接受。

**我是怎么引导 AI 解决的：**

- **先摸清再动手。** 三路并行调查前端（架构与 API 层 / UI 与设计系统 / 测试与工程约定），
  并且明确要求"**不要假设有路由**、实际去读 App.tsx 的渲染分支"。结果是：
  没有路由、只有一个主视图、顶栏嵌在 Workbench 里——这三个事实直接决定了方案形态。
- **筛选必须走后端。** 我明确否掉了"一次拉全量、本地过滤"：上一轮刚为 `?category=`
  和 `filter.matched` 设计了契约，这轮如果不用，答辩时会被问"为什么做了没接"。
- **验收不看截图，驱动真浏览器。** 沿用迭代 3 的做法：playwright-core + 系统已装的 Edge，
  真的点 tab、点 chip、切窄屏，同时收集控制台错误与网络请求。
  这一次更进一步——**读 computed style**，因为第 1 个 Bug 在截图里根本看不出来。

> **这轮最值得讲给评委的一点**：第 1 个 Bug 和迭代 3 的第 3、4 个是同一类——
> **静态截图验证不了"某个东西没生效"**。选中态被覆盖、上限线被裁掉、系列被静默丢弃，
> 表现都是"页面看起来正常，但少了一块"。逼出它们的手段不是更仔细地看图，
> 而是去问浏览器：这个元素**实际算出来的**样式是什么、控制台报了什么、网络发了什么。

调研缺口（访谈原话、受访人数、学分折抵耗时）是它定稿的前置条件。

### 迭代 6 · 2026-10-22 · 补修 / 重修清单（核算入口的另一半）

**这轮要做什么：**

MVP 第 2 项「学分折抵核算」一直是个空壳。这轮先把它拆清楚，再做能诚实地做的那一半。
起点是用户找来几份**别的学校**的学分认定文件，问能不能用来做折抵。

**实际做成了什么：**

- 后端 `analyze_credits`（纯函数）+ `POST /api/plan/credit-gap`：把成绩单与目标培养方案
  分成 **已认定 / 需重修 / 需补修 / 待认定** 四类，并给出建议修读顺序
- 前端第三个 tab「补修核算」：右侧逐行录入已修课程（含「加载示例成绩单」），
  左侧四类清单 + 建议顺序 + 计算说明
- 后端单测 134 → **150**，前端 32 → **53 → 67**
- 真机 Edge 验收：示例成绩单 38 / 1 / 1 / 2，待认定是 CE101；
  拦截请求后旧清单仍在（42 行）+「已过期」徽章

**卡住的地方 / 遇到的 Bug：**

1. **用户找来的四份材料，两份是 0 字节**（下载失败）；有内容的两份是**别的学校**的
   ——上海交大（给换算式）和辽宁石化（要求课程目标等效）。**不能拿来当枣庄学院的规则。**
   但这反而逼出了一个更好的结论：两所学校判定机制完全不同 → 不存在通用答案，
   这恰好是"信息到不了手"的又一条证据。

2. **JSX 里的 `**粗体**` 不会渲染，会原样显示星号。** 我在新视图里写了两处，
   截图里看到字面的 `**` 才反应过来。更意外的是：`ConflictPanel` 里**原本就有一处**
   同样的 bug（空规划提示），一直没人发现。三处一起修了。

3. **测试里把工厂函数当 fixture 用了。** `conftest.completed` 是普通函数不是 fixture，
   写进测试参数会报 "fixture not found"。改用 `from conftest import completed`，
   与 `test_planner.py` 的既有写法一致。

4. **reducer 的 `CLEAR` 会连成绩单一起清空。** 它调用 `emptyPlan()`，而那个函数把
   `completed` 也置空。以前成绩单永远是空的，所以没暴露；这轮一录数据就是个
   数据丢失 bug。改成只清 `items`，并补了回归测试。

**我是怎么引导 AI 解决的：**

- **先划边界，再谈实现。** 我没有问"怎么用这些文件做折抵"，而是先说清楚：
  它们是别的学校的，只能当跨校对照。然后问"哪些部分**不需要**认定办法"——
  这一步把 MVP 第 2 项拆成了可交付与不可交付两半。
- **要求把"待认定"做成一个显式类别**，而不是塞进"补修"里。四类对应四种动作
  （不用管 / 重修 / 补修 / 去问教务处），合并任何一类都会误导。
- 第 2 个 bug 又是**靠截图发现的**：这一轮的重点是数据逻辑，样式只是顺手看了一眼，
  结果看到了字面的星号。说明"看一眼渲染结果"这件事不能省。
- 第 3、4 个都是**写测试时被逼出来的**：写分类测试要先造成绩单，才发现工厂不是 fixture；
  写"清空"测试时才发现它会把成绩单一起清掉。

> **这轮最值得讲给评委的一点**：一份**用不上**的材料也有用。
> 它没能变成功能，却证明了"没有通用规则"，从而让产品把边界画在了正确的位置——
> 补修清单可以算，跨专业折抵不能猜。**知道什么不能做，和知道什么能做一样值钱。**
