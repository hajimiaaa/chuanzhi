### 迭代 1 · 2026-10-15 · 用户调研与定位校准

**这轮要做什么：** 完成转专业学生的痛点验证（立项时唯一的卡点），据此确定 MVP 范围。

**实际做成了什么：**

- 收集到两条信源：同学访谈汇总 + 校园社区三条公开帖（其中一条浏览 822 次、5 条回复）
- 建立 `docs/用户调研.md`：含原话摘录、6 条发现、3 项决策，所有结论可追溯到原话
- **定位从「单入口」改为「双入口」** —— 原定位是"转专业**后**的补修路径规划"，改为"认知入口（查清规则）+ 核算入口（算清学分）"
- 确定 MVP 四项范围与砍单顺序（转专业规则查询排最后，第一个可砍）
- 同步更新 README 痛点段、CLAUDE.md 选题描述、备赛手册待办

**卡住的地方 / 遇到的 Bug：**

- 桌面上的 `访谈.txt` **第一次读取时是 0 字节**——差点直接当成"材料不存在"跳过
- 访谈记录是**汇总转述**，不是原话，违反《备赛手册》"把原话记下来"的要求
- 最麻烦的一处：**调研结论和项目原定位正面冲突**。原卖点是"会不会延毕"，而访谈里明确说"都不太在意延毕"；社区三条帖子也全部集中在"转专业前"，没有一条提到折抵或补修

**我是怎么引导 AI 解决的：**

- 首先，我没有让 AI"帮我找证据支持这个选题"——那样它一定会找到。不如改用**证伪视角**提问："这批数据支持不支持我们原来的定位？哪里对不上？"
- 然后AI 指出了两处硬冲突：① 痛点集中在转专业前；② 笔试卷的是**高中物理与高等数学**，跟培养方案没关系，这等于当面否掉了"工具能帮学生转专业"这个隐含承诺
- 也就是说 AI **主动划出"我们帮不上什么"的边界**（绩点门槛、笔试），写进文档。与其答辩时被评委戳破，不如自己先划清
- 最后由 AI 提出把核心能力重新定义为"**把官方文件变成结构化数据**"——这样"转专业管理办法"和"培养方案"就成了同一种输入，两个入口共用一套引擎，架构不用分叉

> **这轮最值得讲给评委的一点**：AI 的价值不是"帮我把想法实现"，而是"**在我沉浸于自己的想法时，指出数据不支持它**"。前提是我给了它证伪的任务，而不是背书的任务。

**下一轮要做什么：** 后端骨架（数据模型 + 约束引擎）。约束引擎先做纯函数 + 单测，再接 API——保证演示时冲突检测的结果可预测。

### 迭代 2 · 2026-10-15 · 后端骨架（数据模型 + 约束引擎 + 接口）

**这轮要做什么：** 把调研落到代码上。约束引擎先做纯函数 + 单测，再接 API。

**实际做成了什么：**

- `backend/` 从零建成：`config / models / store / constraints / planner / llm / schemas / main` 八个模块
- 手写了一份**明确标注为样例**的培养方案（计算机科学与技术，41 门课 / 8 学期 / 学分门槛 119 / 每学期上限 26）
- 约束引擎 6 个纯函数 + 90 项单测（今天结束时的数字）
- 9 个接口，真机 curl 全部验证通过
- `tools/validate_programs_json.py` —— **零依赖**的数据自检脚本

**卡住的地方 / 遇到的 Bug：**

这轮抓到三个 Bug，其中两个**不是代码写错，而是文档承诺与实现脱节**：

1. **`planner.py` 报的失败原因是错的。** 一门课排不下时，代码说"开课学期与先修课完成时间冲突"——可那门课**根本没有先修课**，它是因为学期学分上限满了。原因判定写成了 if/else 的兜底分支。**这是单测抓出来的**：我断言"排不下时提示里应含『上限』"，测试红了。

2. **README 的复现指南自相矛盾。** 第 71 行用 `backend/requirements.txt`（说明当前目录是仓库根），第 73 行却直接 `uvicorn app.main:app`（要求当前目录是 `backend/`）。评委照抄，**第一步就 `ModuleNotFoundError`**。

3. **`.env` 从来没有被加载过。** README 让人 `cp .env.example .env`、说"填 Key 后重启即可"，但 uvicorn 不读 `.env`，仓库也没装 `python-dotenv`。**这条路从未通过**——想试真 Key 会永远静默降级回 mock，还不报错。

**我是怎么引导 AI 解决的：**

- 我没有让 AI"写完就交"，而是**要求每个模块都有可执行的验收命令**。正是这条让第 1 个 Bug 暴露出来——AI 写了单测，单测把它自己写的兜底分支照出来了
- 第 2、3 个是另一类：我让 AI **把 README 的复现指南当成一份要去执行的东西来读**，而不是当成说明文字。它逐行比对之后发现前后矛盾；`.env` 那条更隐蔽，是靠"读一遍复现步骤然后追代码"才发现的——`uvicorn app.main:app` 后面没有任何加载 `.env` 的环节
- **修法也是 AI 提的**：新建 `config.py`，用 20 行标准库读 `.env`，且**只填空缺、绝不覆盖**已存在的真实环境变量。比装 `python-dotenv` 更可控，也符合项目"少依赖"的取向

> **这轮最值得讲给评委的一点**：三个 Bug 里有两个是**承诺与实现脱节**，而不是算法错误。这类 Bug 不会让程序崩，只会让"按文档走的人"卡住——而我们的提交物里，25% 的分数恰恰压在"评委能不能一键复现"上。所以"让 AI 把文档当成要执行的东西读一遍"，比让它多写一倍的测试更有价值。

**下一轮要做什么：** 前端。先定主视图形态（学期泳道板 vs 依赖图），再定拖拽库，最后才是写组件。

### 迭代 3 · 2026-10-15 · 前端主线闭环 + 后端 SSE 流式增量

**这轮要做什么：** 把闭环做出来——选专业 → 拖拽排课 → 实时冲突 → 学分进度。另外评分表 UX 那 15% 明写了"AI 响应状态提示友好（流式、思考可视化）"，所以还要把后端改成真流式。

**实际做成了什么：**

- 先做后端流式（纯后端、可独立单测、不阻塞前端）：`Provider.stream` + `sse.py` + `POST /api/llm/explain/stream`，15 项单测
- 前端从零建成：Vite 8 + React 19 + TS 6，约 3000 行、25 个源码文件
- 主视图用**学期泳道板**（八列横排、课程卡可跨列拖拽），拖拽用 `@dnd-kit`
- 冲突面板把 16 种冲突分组呈现，点击可联动高亮板上的课程
- 学分进度：Hero 数字 + 4 条类别 meter（CSS）+ 每学期堆叠柱（ECharts）
- 前端 32 项单测（reducer / SSE 解帧 / 本地预判）

**卡住的地方 / 遇到的 Bug：**

前端这轮抓到**四个**，最后一个是这轮最有意思的：

1. **专业列表把三种学制都标成"已接入培养方案"。** 我写了个"去掉括号再匹配"的兜底，结果 `计算机科学与技术` / `（春季）` / `(专升本)` 全被认成了同一个专业。可它们是三个不同的招生口径，而且按《通知》本来就**不在可转专业范围内**。

2. **图表图例里混进了"超出上限"。** 那是我用全透明的占位系列挂标记时留下的噪声。

3. **上限 26 的那条线根本没画出来。** 各学期最高才 21 学分，ECharts 把 y 轴自动收到 25，而上限线在 26 —— **落在坐标区外被静默裁掉**。页面看上去一切正常，线就是不见了。

4. **ECharts 只注册了 `BarChart`，我却用一个 `type:'line'` 的系列去挂上限线，该系列被静默丢弃。** 这个和第 3 个叠加在一起：**我截了两轮图都以为线画好了，其实是看错了**。最后是浏览器控制台的一句 `[ECharts] Series line is used but not imported` 把它揪出来的。

**我是怎么引导 AI 解决的：**

- 第 1 个是靠**截图看图**发现的——把渲染结果当成用户看到的样子去检查，而不是假设"代码写了就是对的"
- 第 2、3 个同样来自看图：图例里多了一项、坐标轴上没有那条线
- 第 4 个换了手段：我发现光看静态截图不够（因为线本来就不该出现，看不出异常），于是**让 AI 装了一个浏览器驱动（playwright-core，用系统已装的 Edge，不下载浏览器）真的去拖了一下**，并收集控制台错误。这一条命令同时验证了四件事：拖拽能不能用、冲突会不会实时出现、点击能不能联动高亮、流式是不是真的在逐字增长

> **这轮最值得讲给评委的一点**：静态截图验证不了"某个东西**没有**出现"。第 3、4 个 Bug 都是这种——程序不报错、页面不异常，功能却缺了一块。逼出它们的不是更仔细的看代码，而是**换一种验证手段**（从看截图换成驱动真实浏览器 + 收集控制台）。而这恰好也是"为什么宁可用真流式而不是假动画"的同一个道理：**能被证伪的东西才值得信**。

**下一轮要做什么：** `docs/技术文档.md`（提交物里唯一还缺的），然后是演示视频。
