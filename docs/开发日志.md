### 迭代 1 · 2026-10-15 · 用户调研与定位校准

**这轮要做什么：** 完成转专业学生的痛点验证（立项时唯一的卡点），据此确定 MVP 范围。

**实际做成了什么：**

- 收集到两条信源：同学访谈汇总 + 校园社区三条公开帖（其中一条浏览 822 次、5 条回复）
- 建立 `docs/用户调研.md`：含原话摘录、6 条发现、3 项决策，所有结论可追溯到原话
- **定位从「单入口」改为「双入口」** —— 原定位是"转专业**后**的补修路径规划"，改为"认知入口（查清规则）+ 核算入口（算清学分）"
- 确定 MVP 四项范围与砍单顺序（转专业规则查询排最后，第一个可砍）
- 同步更新 README 痛点段、CLAUDE.md 选题描述、备赛手册待办

**卡住的地方 / 遇到的 Bug：**

- 桌面上的 `访谈.txt` **第一次读取时是 0 字节**——差点直接当成"材料不存在"跳过
- 访谈记录是**汇总转述**，不是原话，违反《备赛手册》"把原话记下来"的要求
- 最麻烦的一处：**调研结论和项目原定位正面冲突**。原卖点是"会不会延毕"，而访谈里明确说"都不太在意延毕"；社区三条帖子也全部集中在"转专业前"，没有一条提到折抵或补修

**我是怎么引导 AI 解决的：**

- 首先，我没有让 AI"帮我找证据支持这个选题"——那样它一定会找到。不如改用**证伪视角**提问："这批数据支持不支持我们原来的定位？哪里对不上？"
- 然后AI 指出了两处硬冲突：① 痛点集中在转专业前；② 笔试卷的是**高中物理与高等数学**，跟培养方案没关系，这等于当面否掉了"工具能帮学生转专业"这个隐含承诺
- 也就是说 AI **主动划出"我们帮不上什么"的边界**（绩点门槛、笔试），写进文档。与其答辩时被评委戳破，不如自己先划清
- 最后由 AI 提出把核心能力重新定义为"**把官方文件变成结构化数据**"——这样"转专业管理办法"和"培养方案"就成了同一种输入，两个入口共用一套引擎，架构不用分叉

> **这轮最值得讲给评委的一点**：AI 的价值不是"帮我把想法实现"，而是"**在我沉浸于自己的想法时，指出数据不支持它**"。前提是我给了它证伪的任务，而不是背书的任务。

**下一轮要做什么：** 后端骨架（数据模型 + 约束引擎）。约束引擎先做纯函数 + 单测，再接 API——保证演示时冲突检测的结果可预测。
